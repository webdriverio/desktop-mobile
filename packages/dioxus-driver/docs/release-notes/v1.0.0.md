### New:

- **External WebDriver intermediary for Dioxus**: `wdio-dioxus-driver` sits between a WebDriver client and the platform's native WebDriver, and launches your Dioxus app through it, as `tauri-driver` does for Tauri apps. `@wdio/dioxus-service` doesn't start it for `driverProvider: 'external'` yet, so run it yourself and point WebdriverIO's `hostname` and `port` at it
- **Windows support**: Targets msedgedriver and WebView2 on Windows. Linux is blocked until Dioxus exposes Wry's automation toggle, and macOS isn't supported; use `wdio-dioxus-embedded-driver` on those platforms
- **`dioxus:options` capability**: Reads the app to launch and its arguments from `dioxus:options` and maps them onto the native driver's capabilities (`ms:edgeOptions` on Windows)
- **`DIOXUS_WEBVIEW_AUTOMATION`**: Set on the native driver process so the launched app inherits it, which `wdio-dioxus-bridge`'s `automation::is_requested()` reads
- **Port configuration**: `--port` sets the intermediary's port (default `4444`) and `--native-port` the native driver's (default `4445`). `--native-driver` points at a specific native WebDriver binary instead of the one on `PATH`

### Developer:

- **Forked from `tauri-driver`**: The WebDriver proxy is `tauri-driver` (Apache-2.0 OR MIT) with the capability key and automation env var renamed for Dioxus. It tracks upstream `tauri-driver` minor versions
- **Installation**: `cargo install wdio-dioxus-driver --locked`
- **Monorepo**: Developed in the `webdriverio/desktop-mobile` monorepo alongside `@wdio/dioxus-service`
