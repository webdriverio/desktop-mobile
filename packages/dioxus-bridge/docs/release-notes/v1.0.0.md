### New:

- **`install(config)` API**: Wires the bridge into a Dioxus `desktop::Config` in one call, registering the IPC channel, the built-in commands and the guest-js bundle. `install_with_registry(config, registry)` adds app-defined commands. `wdio-dioxus-embedded-driver` calls this for you
- **`wdio://invoke` command bus**: A custom protocol on the webview (`http://wdio.invoke/` on Windows, where WebView2 can't register custom schemes) carries JSON `{ command, args }` requests from the page to Rust handlers on a `CommandRegistry`, returning `{ ok, value }` or `{ ok, error }`
- **Guest-js bundle**: Injected into the webview's `<head>` before any app code runs, exposing `window.__WDIO_DIOXUS__.invoke(command, args)`. `browser.dioxus.execute()` in `@wdio/dioxus-service` passes it to your script as `dx.invoke`, and `browser.dioxus.mock()` intercepts calls made through it
- **Frontend log forwarding**: The guest-js wraps `console.*` and forwards each line through the `log_frontend` command, which writes it to stdout with a `[WDIO-FRONTEND]` marker. `@wdio/dioxus-service` picks these up with `captureFrontendLogs`
- **Multi-window registry**: Labels each Dioxus window in creation order (`main`, `window-1`, …) through `Config::with_on_window`, and exposes the active window, window list and window states to the test process, powering `browser.dioxus.switchWindow()` and `browser.dioxus.listWindows()`
- **Embedded-driver channel**: `install_with_embedded_port(config, port)` tells the guest-js which port the embedded WebDriver server listens on and registers the poll/result commands that `wdio-dioxus-embedded-driver` uses to run WebDriver commands in the page
- **`automation::is_requested()`**: Returns `true` when the app was launched under `@wdio/dioxus-service` (`DIOXUS_WEBVIEW_AUTOMATION=true`), so apps can gate test-only setup
- **Deeplink helper**: `deeplink::register_handler(config, scheme, on_url)` is an optional reference for wiring an in-app handler with `Config::with_custom_protocol`. `browser.dioxus.triggerDeeplink()` works at the OS level and doesn't need it

### Developer:

- **Installed by the embedded driver**: Apps add `wdio-dioxus-embedded-driver`, which depends on this crate and installs it. `install()` on its own doesn't start a WebDriver server
- **Dual package**: Ships as both a Rust crate (`wdio-dioxus-bridge` on crates.io) and an npm package (`@wdio/dioxus-bridge` on npm) containing the guest-js bundle. The built bundle is committed and embedded into the crate at build time by `build.rs`, which fails the build if it's missing
- **Install it last**: Dioxus keeps a single `with_on_window` callback, so install the bridge (through the embedded driver) last in your `Config` builder chain, or call `window_state::register_window` from your own callback
- **Dioxus 0.7**: Built against `dioxus-desktop` 0.7
- **Production safety**: Intended for debug builds only. Wrap the install call in `#[cfg(debug_assertions)]` so it's compiled out of release builds
- **Monorepo**: Developed in the `webdriverio/desktop-mobile` monorepo alongside `@wdio/dioxus-service`
