### New:

- **`emit_deep_link` command**: Emits the deep-link plugin's `deep-link://new-url` event on the app's main thread, so `browser.tauri.triggerDeeplink()` reaches the app's `onOpenUrl` / `on_open_url` handlers. Its permission, `wdio:allow-emit-deep-link`, is in `wdio:default` ([#857](https://github.com/webdriverio/desktop-mobile/pull/857))

### Breaking Changes:

- **WebdriverIO v9 and v10**: `@wdio/tauri-plugin` and `tauri-plugin-wdio` 2.0 pair with `@wdio/tauri-service` 2.0, which supports both, with `webdriverio` `^9.33.0 || ^10.2.0`. Update the npm package and the crate together with the service and `tauri-plugin-wdio-webdriver`. See [Update the service, the plugin and the embedded driver together](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#update-the-service-the-plugin-and-the-embedded-driver-together) ([#1015](https://github.com/webdriverio/desktop-mobile/pull/1015))
- **Node.js**: `@wdio/tauri-plugin` declares Node.js 22.23.4+, 24.22.1+ or 26.12.1+; 23.x and 25.x aren't supported. It runs in the app, so this only constrains the app's build. See [Node.js](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#nodejs) ([#797](https://github.com/webdriverio/desktop-mobile/pull/797), [#916](https://github.com/webdriverio/desktop-mobile/pull/916))
- **`@tauri-apps/api` is a peer**: `@wdio/tauri-plugin` takes the app's `@tauri-apps/api` (`^2.10.0`) instead of an exact 2.12.1 of its own, and no longer brings `@tauri-apps/plugin-log`. See [`@tauri-apps/api` is a peer](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#tauri-appsapi-is-a-peer-of-wdiotauri-plugin) ([#799](https://github.com/webdriverio/desktop-mobile/pull/799))
- **Tauri 2.10**: `tauri-plugin-wdio` requires `tauri` 2.10+, where it declared an untested 2.0.0. See [Tauri 2.10 and Rust](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#tauri-210-and-rust) ([#799](https://github.com/webdriverio/desktop-mobile/pull/799))
- **Mocks see the app's own calls**: The frontend plugin intercepts the IPC requests behind `@tauri-apps/api`'s `invoke()`, `window.__TAURI__.core.invoke` and `emit()`, so a mock applies to the commands the app invokes itself. The old `window.__TAURI__.core` wrapper, which Tauri's frozen object never let install, is gone, and `cleanupInvokeInterception()` restores `fetch`. See [Mocks see the commands the app invokes](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#mocks-see-the-commands-the-app-invokes) ([#1017](https://github.com/webdriverio/desktop-mobile/pull/1017))
- **Deeplink permission**: `triggerDeeplink()` needs `wdio:allow-emit-deep-link`. An app that lists the plugin's permissions one by one, instead of `wdio:default`, must add it. See [Deeplinks](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#deeplinks) ([#857](https://github.com/webdriverio/desktop-mobile/pull/857))
- **`execute()` script argument**: A script gets `{ core: { invoke } }` and then its own arguments, and `core.invoke` takes a command and at most an args object. See [A `browser.tauri.execute()` script's first argument](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#a-browsertauriexecute-scripts-first-argument) ([#860](https://github.com/webdriverio/desktop-mobile/pull/860), [#896](https://github.com/webdriverio/desktop-mobile/pull/896))
