### New:

- **Embedded W3C WebDriver server**: `wdio-dioxus-embedded-driver` runs a WebDriver HTTP server inside your Dioxus app's process, so there's no driver to install. Call `wdio_dioxus_embedded_driver::install(config)` once and `@wdio/dioxus-service` connects to it
- **Full cross-platform support**: macOS, Windows and Linux are all supported in this release. Commands run in the page through the bridge's IPC channel, so the server needs no native webview handle
- **56 W3C WebDriver endpoints**: Session management, navigation, script execution, element finding and interaction (including element screenshots), window management, frames, cookies, user actions, alerts, page source, screenshots, and PDF printing
- **Installs the bridge**: `install()` also installs `wdio-dioxus-bridge`, so `browser.dioxus.execute()`, mocking, log forwarding and multi-window support work without further wiring. `install_with_commands(config, |registry| …)` registers app-defined commands too
- **`WDIO_EMBEDDED_PORT` env var**: Configure the server port at runtime without code changes. `@wdio/dioxus-service` sets this automatically. Falls back to port `4444`. The server listens on `127.0.0.1`
- **Per-port webview data directory**: Each instance uses its own WebView2/WebKit data directory in the system temp folder (`wdio-dioxus-<port>`), so parallel and multiremote instances don't share state
- **Readiness endpoint**: `GET /status` reports `ready: true` once a window has registered with the bridge. The service polls it before creating the session

### Developer:

- **Re-exports `automation`**: `wdio_dioxus_embedded_driver::automation::is_requested()` lets apps gate test-only setup without depending on the bridge directly
- **Production safety**: Intended as a dev/test-only dependency. Wrap the install call in `#[cfg(debug_assertions)]` (or a Cargo feature) so the server is compiled out of release builds
- **Monorepo**: Developed in the `webdriverio/desktop-mobile` monorepo alongside `@wdio/dioxus-service`
