### New:

- **WebdriverIO v10**: The service runs on WebdriverIO v10 as well as v9. See [WebdriverIO v10](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#webdriverio-v10) ([#792](https://github.com/webdriverio/desktop-mobile/pull/792), [#794](https://github.com/webdriverio/desktop-mobile/pull/794), [#796](https://github.com/webdriverio/desktop-mobile/pull/796))
- **Weston on Linux**: With WebdriverIO v10, the `embedded` and `external` providers are tested on Weston as well as Xvfb, and need no `xvfb-run` wrapper ([#809](https://github.com/webdriverio/desktop-mobile/pull/809), [#879](https://github.com/webdriverio/desktop-mobile/pull/879), [#890](https://github.com/webdriverio/desktop-mobile/pull/890))

### Breaking Changes:

- **WebdriverIO 9.33.0+**: On WebdriverIO v9, `webdriverio`, `@wdio/globals` and `@wdio/types` need 9.33.0 or later, and on v10, 10.2.0 or later (`^9.33.0 || ^10.2.0`). See [WebdriverIO 9.33.0+](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#webdriverio-9330) ([#1015](https://github.com/webdriverio/desktop-mobile/pull/1015))
- **Node.js**: 22.23.4+, 24.22.1+ or 26.12.1+ is required; 23.x and 25.x aren't supported. See [Node.js](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#nodejs) ([#797](https://github.com/webdriverio/desktop-mobile/pull/797), [#916](https://github.com/webdriverio/desktop-mobile/pull/916))
- **Optional peers**: `webdriverio`, `@wdio/globals` and `@wdio/types` are optional peers. Standalone mode, pnpm without hoisting and Yarn Plug'n'Play need them installed. See [optional peers](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#webdriverio-packages-are-optional-peers) ([#798](https://github.com/webdriverio/desktop-mobile/pull/798), [#724](https://github.com/webdriverio/desktop-mobile/pull/724))
- **Paired packages**: Update `@wdio/tauri-plugin`, `tauri-plugin-wdio` and `tauri-plugin-wdio-webdriver` to 2.0 with the service. Both crates require tauri 2.10+ and declare the Rust versions they build with. See [Update the service, the plugin and the embedded driver together](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#update-the-service-the-plugin-and-the-embedded-driver-together) ([#799](https://github.com/webdriverio/desktop-mobile/pull/799), [#1002](https://github.com/webdriverio/desktop-mobile/pull/1002))
- **`driverProvider: 'official'` removed**: Use `'external'`. Any other unknown value stops the run. The unexported `executeTauriCommand()` helpers are gone too. See [`driverProvider: 'official'` is removed](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#driverprovider-official-is-removed) ([#802](https://github.com/webdriverio/desktop-mobile/pull/802))
- **`commandTimeout` and `rootDir` removed**: Neither took effect. Set WebdriverIO's `connectionRetryTimeout` instead of `commandTimeout`. See [`commandTimeout` is removed](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#commandtimeout-is-removed) ([#832](https://github.com/webdriverio/desktop-mobile/pull/832), [#947](https://github.com/webdriverio/desktop-mobile/pull/947))
- **`appArgs` and `env`**: They reach the app with the `external` and `crabnebula` providers, and `tauri:options.args` replaces `appArgs`. `tauriDriverPort`, `autoDownloadEdgeDriver` and `edgeDriverVersion` are service-level only, and a failing `onPrepare` or `onWorkerStart` stops the run. See [`appArgs` and `env`](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#appargs-and-env-reach-the-app-with-every-provider) ([#951](https://github.com/webdriverio/desktop-mobile/pull/951))
- **`webviewOptions`**: No longer accepts `width` or `height`, which never had an effect. See [`webviewOptions`](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#webviewoptions-no-longer-takes-width-or-height) ([#958](https://github.com/webdriverio/desktop-mobile/pull/958))
- **`embeddedPort`**: Is a preferred port. A busy one is skipped for a free port. See [`embeddedPort`](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#embeddedport-is-a-preferred-port) ([#807](https://github.com/webdriverio/desktop-mobile/pull/807))
- **Mocks see the app's own calls**: In native mode, a mock also applies to the commands the app invokes itself. See [Mocks see the commands the app invokes](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#mocks-see-the-commands-the-app-invokes) ([#1017](https://github.com/webdriverio/desktop-mobile/pull/1017))
- **Mock call data and failures**: A failed bulk mock operation tries every mock, then throws one error. Recorded calls keep `undefined` arguments, and browser-mode mocks record only the args. See [Mocking](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#mocking) ([#744](https://github.com/webdriverio/desktop-mobile/pull/744), [#1044](https://github.com/webdriverio/desktop-mobile/pull/1044), [#1022](https://github.com/webdriverio/desktop-mobile/pull/1022))
- **`withImplementation()` and `execute()`**: An async `withImplementation()` callback keeps the implementation until it settles. A `browser.tauri.execute()` script gets `{ core: { invoke } }`, and `core.invoke` takes at most an args object. See [`withImplementation()`](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#withimplementation-waits-for-a-returned-promise) ([#896](https://github.com/webdriverio/desktop-mobile/pull/896), [#860](https://github.com/webdriverio/desktop-mobile/pull/860))
- **Element references in script results**: `browser.execute()` and `browser.tauri.execute()` return DOM elements as W3C references, and a `NodeList` as an array. See [Scripts and `execute()`](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#scripts-and-execute) ([#1016](https://github.com/webdriverio/desktop-mobile/pull/1016), [#1042](https://github.com/webdriverio/desktop-mobile/pull/1042), [#1049](https://github.com/webdriverio/desktop-mobile/pull/1049))
- **Embedded driver behaviour**: `change` timing, Clear's events, key codes, Shift, Tab, Enter, Element Click events and `releaseActions()` order now match Chrome. See [Embedded Driver Behaviour](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#embedded-driver-behaviour) ([#827](https://github.com/webdriverio/desktop-mobile/pull/827), [#828](https://github.com/webdriverio/desktop-mobile/pull/828), [#898](https://github.com/webdriverio/desktop-mobile/pull/898), [#910](https://github.com/webdriverio/desktop-mobile/pull/910), [#919](https://github.com/webdriverio/desktop-mobile/pull/919), [#924](https://github.com/webdriverio/desktop-mobile/pull/924), [#964](https://github.com/webdriverio/desktop-mobile/pull/964), [#965](https://github.com/webdriverio/desktop-mobile/pull/965), [#978](https://github.com/webdriverio/desktop-mobile/pull/978), [#1041](https://github.com/webdriverio/desktop-mobile/pull/1041), [#1094](https://github.com/webdriverio/desktop-mobile/pull/1094))
- **Deeplinks**: `triggerDeeplink()` emits the deep-link plugin's event, so the app's handlers receive it, and needs the `wdio:allow-emit-deep-link` permission. In multiremote it throws where the OS can't deliver the URL. See [Deeplinks](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#deeplinks) ([#826](https://github.com/webdriverio/desktop-mobile/pull/826), [#857](https://github.com/webdriverio/desktop-mobile/pull/857), [#804](https://github.com/webdriverio/desktop-mobile/pull/804), [#1010](https://github.com/webdriverio/desktop-mobile/pull/1010))
- **Standalone mode**: `startWdioSession()` uses WebdriverIO's request timeout and retries, and `cleanupWdioSession()` runs `after` and `afterSession` before it deletes the session. See [Standalone Mode](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#standalone-mode) ([#883](https://github.com/webdriverio/desktop-mobile/pull/883), [#864](https://github.com/webdriverio/desktop-mobile/pull/864))
- **Browser mode**: Each capability opens its own `devServerUrl`, mixed modes stop the run, and `devServer` is a service-level option. See [Browser Mode](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#browser-mode) ([#953](https://github.com/webdriverio/desktop-mobile/pull/953))
- **Multiremote**: Each instance gets its own mocks, mock options and `windowLabel`, and mixed `driverProvider` values stop the run. See [Multiremote](https://github.com/webdriverio/desktop-mobile/blob/wdio-tauri-service@v2.0.0/packages/tauri-service/docs/migration/v1-to-v2.md#multiremote) ([#899](https://github.com/webdriverio/desktop-mobile/pull/899), [#930](https://github.com/webdriverio/desktop-mobile/pull/930), [#950](https://github.com/webdriverio/desktop-mobile/pull/950))

### Fixed:

- An unset `driverProvider` is treated as `'embedded'` in the worker, as in the launcher ([#806](https://github.com/webdriverio/desktop-mobile/pull/806))
- `logLevel` applies to `tauri-driver`'s output ([#825](https://github.com/webdriverio/desktop-mobile/pull/825))
- Standalone `startWdioSession()` honours the service-level `startTimeout` and log options ([#816](https://github.com/webdriverio/desktop-mobile/pull/816))
- In native mode, `browser.tauri.emitEvent()` reaches the app's listeners ([#858](https://github.com/webdriverio/desktop-mobile/pull/858))
- A mock targets the window it was registered in ([#869](https://github.com/webdriverio/desktop-mobile/pull/869))
- Driver teardown stops every driver after a failure, then reports it ([#744](https://github.com/webdriverio/desktop-mobile/pull/744))
- On Linux, an async script that never calls `done` fails with `script timeout`, not `javascript error` ([#1035](https://github.com/webdriverio/desktop-mobile/pull/1035))
- The service writes to WebdriverIO's log file instead of a second `@wdio/logger` copy's ([#724](https://github.com/webdriverio/desktop-mobile/pull/724))
